# PALA 0.3.4 — تصمیم قطعی: STT و TTS آزاد و قابل توسعه

تاریخ: ۲۰ نوامبر ۲۰۲۶. شاخه آزمایشی: pala/integrated-034-2026-11-17

## تصمیم مالک
STT و TTS هرگز به فهرست ثابت سه موتور Android/Whisper/Vosk یا دو موتور TTS محدود نباشند. کاربر باید بتواند چند موتور و چند مدل تحت یک موتور (از جمله Vosk کوچک و بزرگ)، نصب، آزمون، مقایسه، انتخاب و حذف کند. انتخاب STT مستقل از TTS و ذخیره شده باشد؛ مدل جدید با آداپتور موجود بدون انتشار هسته جدید پذیرفته شود.

Android Offline STT فارسی در دستگاه مالک قابل استفاده نبوده، Whisper فارسی در آزمون قبلی خطاهای فراوان داشته و Vosk روی Galaxy Tab S10 Ultra هنوز آزمون نشده است. نتیجه مطلوب PVM/Vosk2 روی سیستم دیگر، قبولی PALA روی تبلت نیست. صدای فارسی فعلی Android TTS را نباید بدون دلیل تغییر داد.

## معماری لازم
۱. Adapter registry: هر backend باید شناسه، نوع STT/TTS، زبان، فرمت مدل، نسخه، قرارداد ورودی/خروجی، نیاز CPU/RAM و گزارش آمادگی داشته باشد. آداپتور اجرایی باید واقعاً متصل و آزموده شده باشد.
۲. Model registry: چند مدل مستقل برای هر backend؛ نام، منشأ، اندازه، SHA-256 (برای دانلود)، مسیر محلی، وضعیت، انتخاب فعال، حذف مستقل و rollback. مدل تازه با آداپتور سازگار باید بدون توسعه هسته اضافه شود.
۳. UI مدیریت یکپارچه: نصب اختیاری از منبع معتبر یا فایل محلی، آزمون صوتی با متن نهایی، A/B و دقت/تأخیر/RAM، خطای فارسی قابل‌فهم، غیرفعال کردن موتور ناسازگار. هیچ بسته اضافه بدون درخواست مالک دانلود نشود.
۴. STT و TTS مستقل با engine+model IDs؛ مدل انتخابیِ فاقد آداپتور باید حفظ ولی اجرا نشود. نباید با Android STT، Whisper، Kokoro یا موتور دیگری بی‌صدا جایگزین شود.
۵. سازگاری با اجرای آفلاین: هیچ STT/TTS ابری، سرویس پولی، یا API شبکه بدون مجوز صریح؛ حفظ همه داده‌ها و برنامه اصلی.
۶. افزودن موتور جدید با فرمت اجرایی متفاوت نیازمند آداپتور مناسب است. صرفاً قرار دادن هر فایل دلخواه در پوشه، دلیل قابل‌اجرا بودن آن نیست؛ فهرست موتورهای دارای آداپتور نباید سقف نهایی مدل‌ها/توسعه باشد.

## معیارهای پذیرش
- مدل دوم Vosk (یا موتور/مدل دیگر با آداپتور موجود) از UI وارد، تأیید، فعال و بدون دست‌زدن به مدل اول آزموده شود.
- برای TTS نیز صدای فارسی قابل‌انتخاب از فهرست باز، مستقل از STT؛ هنگام عدم سازگاری خطای روشن و عدم اجرای موتور دیگر.
- تست گفتار فارسی محاوره‌ای با اینترنت قطع و انتقال متن واقعی به Qwen در Galaxy Tab S10 Ultra.
- دانلود مدل فقط با انتخاب کاربر و امکان حذف و بازگشت.
- تست رگرسیون، CI و تست روی تبلت قبل از ادعای پذیرش نهایی.

## وضعیت فعلی (شفاف)
PALA هنوز فهرست اجرایی محدود به آداپتورهای موجود دارد. این سند تصمیم اصلاح معماری و معیار پذیرش است، نه ادعای تکمیل import هر موتور. تکمیل Model/Adapter registry، انتخاب آزاد در UI، ورود فایل، A/B و پشتیبانی از TTSهای غیراندرویدی هنوز باز است. شاخه main و APK 0.3.3+6 و Home Assistant/PVM باید دست‌نخورده بمانند.


## پیشرفت مشترک مأموریت‌های ۰۹ و ۱۰ — ۲۰ نوامبر ۲۰۲۶
- پیاده‌سازی عملی واردکردن فایل ZIP برای چند مدل Vosk در UI اضافه شد؛ هر مدل با ID و پوشه مستقل، بدون حذف مدل قدیمی و بدون دانلود خودکار ذخیره می‌شود. هر دو ساختار graph/HCLG.fst و graph/Gr.fst + graph/HCLr.fst پذیرفته می‌شوند؛ مدل نامعتبر اجرا نمی‌شود.
- انتخاب و آزمون موتورهای **نصب‌شده** Android TTS از فهرست پویا برقرار است؛ انتخاب صدای فارسی آفلاین درون هر موتور و ذخیره انتخاب مستقل اضافه شد. HayaiTTS/Gyro فقط در صورت شناسایی روی دستگاه امکان آزمایش دارند.
- انتخاب‌های STT و TTS از نظر مدل مستقل‌اند؛ مسیرهای ناموجود بی‌اجازه به موتور دیگری تبدیل نمی‌شوند. مکالمه یک‌جمله‌ای Vosk بعد از مکث، متن نهایی را به مسیر Qwen می‌فرستد و پخش پاسخ از مسیر TTS آفلاین انجام می‌شود.
- **باز بودن به معنی اجرای خودکار هر فایل موتور نیست**: مدیر عمومی آداپتورهای قابل‌نصب برای موتورهای نامرتبط و پشتیبانی از Piper/Pocket و سایر TTSهای native، همچنین مقایسه A/B کامل، هنوز کار توسعه‌ای مستقل دارند. بدون آداپتور سازگار ادعای READY مجاز نیست.
- آزمون دستگاه واقعی / مایکروفون / RAM و بارگیری مدل روی Galaxy Tab S10 Ultra هنوز انجام نشده است. CI حتی با SUCCESS جایگزین آن نیست؛ برای پروتکل مراجعه شود به [گزارش یکپارچه M09/M10](PALA_034_M09_M10_Voice_Integration_2026-11-20_FA.md).
