# PALA — مأموریت ۱۴: HA Doctor اولیه و فقط‌خواندنی

تاریخ: ۲۰ نوامبر ۲۰۲۶
شاخه توسعه: pala/m14-ha-doctor-2026-11-20
وضعیت: توسعه روی GitHub، بدون انتشار یا نصب.

## مبنا و هدف
این توسعه ادامه مستقیم نسخه آزمایشی مأموریت ۱۳ است. از اتصال محلی موجود Home Assistant، تنظیمات قدیمی و توکن نگهداری‌شده در Secure Storage استفاده می‌شود؛ هیچ سرور، توکن یا API پولی جدیدی نیاز ندارد.

## قابلیت اولیه
- پرسش تشخیصی فارسی مانند «چکاپ سلامت سیستم» یا «چرا Home Assistant کند شده؟» در گفت‌وگوی معمولی و همه پروژه‌های پالا، به یک بررسی محلی و فقط‌خواندنی متصل می‌شود.
- پیش‌فرض غیرفعال است؛ مالک می‌تواند یک‌بار در صفحه اتصال Home Assistant گزینه «بررسی فقط‌خواندنی سلامت سیستم» را فعال کند. درخواست خواندن حسگر قبلی، به‌تنهایی مجوز لاگ نیست.
- فقط درخواست‌های GET ثابت به API محلی Home Assistant مجازند: config، error_log، و حداکثر سه حسگر از فهرست قبلاً مجاز. سقف حجم، timeout و رد redirect برقرارند.
- تنها فیلدهای غیرحساس نسخه Core و شمار اجزای config استخراج می‌شود؛ نام خانه و مختصات هرگز وارد پاسخ یا مدل نمی‌شوند. لاگ خام فقط در حافظه برنامه طبقه‌بندی و شمارش می‌شود و متن آن نمایش یا ذخیره نمی‌شود.
- پاسخ فارسی قطعی و مبتنی بر قواعد است: نشانه خطا، اطمینان، منابع مشاهده، محدودیت تفسیر لاگ، بررسی‌های کم‌خطر. هیچ تشخیص یا عددی توسط Qwen حدس زده نمی‌شود.
- سندهای محلی انتخاب‌شده در همان پروژه، اگر مرتبط باشند، به عنوان «راهنما» جدا از شاهد واقعی فهرست می‌شوند؛ هیچ سندی علت خرابی زنده را اثبات نمی‌کند.
- Core version قابل مشاهده است. OS/Supervisor، جزئیات همه Integrationها، وضعیت واقعی SSD/RAM/CPU و بکاپ‌ها، تا زمانی که داده معتبرِ فقط‌خواندنی برایشان وجود ندارد، «نامعلوم» گزارش می‌شوند.
- هیچ Restart، Restore، تنظیمات، HA write، کنترل تجهیزات، نصب، حذف فایل یا اقدام تعمیر خودکار انجام نمی‌شود.

## معیار پذیرش نمونه
آزمون شبیه‌سازی‌شده خطای SQLite شامل database disk image is malformed و disk I/O error. گزارش باید نشانه خطای Recorder را با اطمینان درباره متن مشاهده‌شده ارائه دهد، ولی زمان فعال‌بودن مشکل و خرابی فیزیکی SSD را قطعی نداند. هیچ اطلاعات خصوصی از config یا log به گزارش نفوذ نکند. در آزمون HTTP، روش تمام درخواست‌ها GET و مسیرها ثابت باشند. نبود مجوز یا عدم دسترسی به لاگ، «نامعلوم» اعلام شود.

## پذیرش عملی
آزمون واقعی روی تبلت و Home Assistant انجام نشده و نتیجه تاریخی Recorder در منبع پروژه به معنی وضعیت کنونی نیست. پس از تکمیل آزمون‌های GitHub، انتشار باید همراه سایر مأموریت‌ها، بکاپ، حفظ مدل و داده، قابلیت بازگشت و یک آزمایش میدانی کم‌خطر انجام شود.
